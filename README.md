# ふたりアルバム

カップル向けの写真・動画アルバムのウェブアプリです。
紙のアナログアルバムのような見た目で、写真・動画に「タイトル」「ひとことコメント」「日付」を付けて、月ごとにまとめて眺められます。
メッセージやカレンダーの機能はなく、アルバム専用です。

## できること

- 写真・動画を追加する（ボタンから選択、またはページへのドラッグ＆ドロップ。複数まとめて選べます）
- 追加するときにタイトル・コメント・日付を入力する
  - 日付の初期値：JPEG の EXIF 撮影日時 → なければファイルの更新日時 → なければ今日
  - 日付は手入力で変更できます
  - 複数を追加するときは 1 枚ずつ入力するか、「残りはこのまま全部貼る」で一括保存できます
- カードを押すと、あとからタイトル・コメント・日付を編集したり、削除（「はがす」）したりできます
- 月ごとにまとめて表示します（例：2026年11月）。新しい月・新しい日付が上に来ます
- **Google Drive に保存します（既定）**。写真・動画の実体とメタデータ（`album-metadata.json`）を、既存の Drive フォルダ「ふたりアルバム」に保存します
  - 画面上部の「Google でサインイン」でサインインすると、アルバムが表示されます
  - 「はがす」で削除したメディアは Drive のゴミ箱へ移動します（完全削除はしません。Drive のゴミ箱から 30 日以内なら戻せます。ただしアルバムの記録からは外れます）
  - 同じフォルダにアクセスできる Google アカウントなら、別の端末・別の人からでも同じアルバムを見られます（共有は後述の手順 5、未実施）
- Drive 連携が未設定（`clientId` が空）のあいだは「Drive 連携は準備中です」と表示されます。「この端末だけで試す（ローカル保存）」を押すと、そのタブではブラウザ内（IndexedDB）に保存して試せます（「Drive 保存に戻す」で戻ります）
- `js/config.js` の `storage.backend` を `"indexeddb"` にすると、従来どおりブラウザ内（IndexedDB）だけに保存します（認証バーは出ません）
- 「記録を書き出す」で、メタデータ（タイトル・コメント・日付など）を JSON ファイルとしてダウンロードできます（メディアの実体は含みません）
- 件数の上限は設けていません（上限は Drive の保存容量、IndexedDB の場合はブラウザの保存容量だけです）

見た目：白フチの写真カード、Klee One（手書き風）のキャプション、マスキングテープ風の装飾、紙のような背景。UI の文字は Zen Maru Gothic を使っています（どちらも Google Fonts）。

## 起動方法

ビルドは不要です。

- いちばん簡単：`index.html` をブラウザ（Chrome / Edge / Safari / Firefox の最新版）で開く
- 簡易サーバーで開く場合：
  ```sh
  cd futari-album
  python3 -m http.server 8000
  # → http://localhost:8000/ を開く
  ```

注意：
- **Google Drive 保存を使うときは `http://localhost:8000` か公開 URL（GitHub Pages）で開いてください。** `index.html` の直開き（file://）では Google のサインインが動きません。また、OAuth クライアントの「承認済み JavaScript 生成元」に登録したオリジン以外でもサインインできません。
- IndexedDB 保存のデータは「開いたブラウザ」と「開き方（ファイル直開き か http://localhost か）」ごとに別々に保存されます。いつも同じ開き方で使ってください。
- フォントは Google Fonts から読み込むため、オフラインのときは代わりのフォントで表示されます。

## Google Drive の保存先

| 項目 | 値 |
|---|---|
| フォルダ名 | ふたりアルバム |
| フォルダ ID | `15Z7Z42_sIklsHElIYJDvZz7LhR_t33Ca` |

`js/config.js` の `storage.gdrive.folderId` に記録済みです。このフォルダはこのアプリが作ったものではなく、別ツールで作成済みのものです。

フォルダの中身：
- 写真・動画ファイル（元のファイル名でアップロード。ファイル名が無い場合は `ID＋拡張子`）
- `album-metadata.json` … アルバムの記録（Item の配列）。**手で編集・削除しないでください**（壊れると読み込めなくなります。壊れた JSON を空で上書きすることはしない作りにしています）

### 認証スコープがフル Drive（`.../auth/drive`）である理由

- `drive.file` スコープでは「このアプリが作成した（またはこのアプリで開いた）ファイル」にしかアクセスできません。保存先フォルダ「ふたりアルバム」は別ツールで作成済みの既存フォルダなので、`drive.file` ではこのフォルダの中身を読み書きできません。
- そのため既定のスコープは `https://www.googleapis.com/auth/drive` にしています（`js/config.js` の `gdrive.scopes`。配列のまま編集できます）。
- ただし、コード上の Drive API 呼び出しは **対象フォルダ（`folderId`）配下だけ** に限定しています。
  - ファイル一覧・検索は必ず `'<folderId>' in parents` で絞り込み、フォルダ外を列挙・検索しません
  - 個別ファイルにアクセスするのは、フォルダ内の `album-metadata.json` と、アルバムが自分でアップロードして記録したメディアだけです
  - ゴミ箱へ移動する前に、そのファイルが対象フォルダ内にあることを確認します（フォルダ外へ移されていたら触りません）
  - フォルダやファイルの **共有設定（権限）は一切変更しません**
- アクセストークンはブラウザのメモリ内にだけ保持し、保存はしません（タブを閉じる・リロードすると破棄されます。有効期限はおよそ 1 時間）。

### 容量についての注意

Drive に保存した写真・動画は、**サインインした Google アカウントの保存容量**（無料枠は Gmail・Google フォトと合わせて 15GB）を使います。動画は特に容量を使うので、残り容量に注意してください。共有後にあきらが追加したファイルは、通常あきらのアカウントの容量にカウントされます（未確認：Google 側の仕様に依存します）。

## メタデータの形式

1 件ごとに次の JSON オブジェクトで管理します（全体は配列）。例は `data/sample-data.json` を参照してください。

```json
{
  "id": "6f1c2a9e-3b7d-4c1e-9a52-1d0f8e7b6a01",
  "title": "はじめての鎌倉",
  "comment": "しらす丼おいしかったね",
  "date": "2026-11-03",
  "kind": "photo",
  "createdAt": "2026-11-04T10:15:00.000Z",
  "fileName": "IMG_0123.jpg",
  "mimeType": "image/jpeg",
  "size": 2483011,
  "mediaRef": "6f1c2a9e-3b7d-4c1e-9a52-1d0f8e7b6a01"
}
```

| キー | 型 | 説明 |
|---|---|---|
| id | string | 一意 ID（UUID） |
| title | string | タイトル（空でも可。表示は「無題」） |
| comment | string | ひとことコメント（空でも可） |
| date | string | 撮影日 `YYYY-MM-DD`。月別グルーピングに使う |
| kind | `"photo"` \| `"video"` | 種類 |
| createdAt | string | アルバムに登録した日時（ISO 8601） |
| fileName / mimeType / size | | 元ファイルの情報（補助） |
| mediaRef | string | メディア実体への参照。IndexedDB では id と同じ、Drive ではアップロードしたファイルの fileId |

## 保存アダプタ（差し替えの仕組み）

`app.js` は `js/storage.js` の共通インターフェースだけを使います。

```
init() / list() / add(meta, file) / update(id, patch) / remove(id) / getMedia(id) / exportMetadata()
```

- `GoogleDriveAdapter`（既定）… Google Identity Services でサインインし、Drive API（fetch）でフォルダ内に保存
  - 追加：メディアを multipart アップロード → fileId を `mediaRef` に記録 → `album-metadata.json` に追記
  - 編集：`album-metadata.json` を読み直してから該当項目（title / comment / date）だけ変更して保存
  - 削除：メディアをゴミ箱へ移動（`trashed: true`）→ 記録から外して保存
  - メタデータの読み書きは内部で直列化し、同時保存で上書きし合わないようにしています
  - 追加の認証メソッド：`signIn()` / `signOut()` / `isSignedIn()`、状態 `state`（`"unconfigured"` / `"ready"` など）
- `IndexedDBAdapter`（フォールバック）… ストア `items` にメタデータ、ストア `media` にファイル実体（Blob）を保存

`js/config.js` の `storage.backend` を `"gdrive"` / `"indexeddb"` で切り替えます。

## 未実装事項

Drive 連携の実装は完了しています。残っているのは **本人のセットアップ（下の手順 1〜4）と、あきらとの共有（手順 5）だけ** です。

アプリとしての未対応・制限：
- 既存の IndexedDB（ローカル保存）データを Drive へ移す移行処理
- JSON の読み込み（インポート）。書き出しのみ対応
- 動画の撮影日の自動取得（動画はファイルの更新日時を初期値にしています）
- HEIC・PNG などの EXIF 読み取り（JPEG のみ対応）。HEIC はブラウザによっては表示できません
- サムネイル生成：一覧表示のたびに全メディアを Drive からダウンロードしています。件数や動画が多いと表示が遅く、通信量も多くなります
- 大きな動画のアップロード：multipart アップロードを使っています。Google は 5MB 超のファイルにはレジューム可能アップロードを推奨しているため、大きな動画では失敗・タイムアウトする可能性があります（未確認：実機での上限は未検証）
- サインインの有効期限（約 1 時間）が切れると、次の保存操作のときにサインイン画面が開き直します。リロードした場合もサインインし直しになることがあります
- ふたりで同時に編集した場合、ほぼ同時の保存は後から保存した方が優先されます（同じ端末内の同時保存は直列化済み。別端末どうしの排他制御はしていません）
- 並べ替え・検索・絞り込み、アプリ内のゴミ箱（Drive のゴミ箱から 30 日以内なら手動で戻せますが、アルバムの記録には戻りません）

### 1. GitHub で公開する（ホスティング）

> **現在の状態（2026-11-04 時点）**：このフォルダは git 初期化と初回コミットまで済んでいます（リモートとして `https://github.com/p418822san-dev/futari-album.git` を設定済み）。ただし、この作業環境（Muse のマシン）には GitHub の認証情報がないため、**リポジトリ作成と push はまだ行えていません**。残りは次の 2 つだけです。

1. GitHub にサインインし、右上の「＋」→「New repository」
2. Repository name：`futari-album`、公開範囲：**Public** を選んで「Create repository」（README 等は追加しない＝空のリポジトリにする）
3. このフォルダから push する（push には GitHub の認証が必要です。認証済みの環境から実行してください）
   ```sh
   cd futari-album
   git push -u origin main
   ```
   （`index.html` がリポジトリの一番上に来る構成になっています）
4. リポジトリの「Settings」→ 左メニュー「Pages」→「Build and deployment」の Source で **Deploy from a branch** を選び、Branch を **main**、フォルダを **/ (root)** にして「Save」
5. 数分待つと公開されます。公開 URL は **`https://p418822san-dev.github.io/futari-album/`** になる見込みです
   - ※ GitHub のアカウント名が `p418822san-dev` でない場合は、URL の `p418822san-dev` の部分を自分のアカウント名に読み替えてください（以降の手順も同様）。リモート URL が変わる場合は `git remote set-url origin <新しいURL>` で直してください

※ Public リポジトリなので、コード（`config.js` のフォルダ ID・クライアント ID を含む）は誰でも見られます。どちらも秘密情報ではなく、Drive の中身は Google アカウントでサインインして権限がある人しか見られません。写真・動画そのものはリポジトリには入りません。

### 2. Google Cloud Console の設定

1. https://console.cloud.google.com/ を開き、上部のプロジェクト選択 →「新しいプロジェクト」→ プロジェクト名「**ふたりアルバム**」で作成し、そのプロジェクトを選択する
2. 左メニュー「API とサービス」→「ライブラリ」→「**Google Drive API**」を検索して「有効にする」
3. 「API とサービス」→「OAuth 同意画面」（表示によっては「Google Auth Platform」→「ブランディング／対象／データアクセス」）で設定する
   - User Type：**外部**
   - アプリ名：**ふたりアルバム**
   - ユーザーサポートメール・デベロッパーの連絡先：**自分のメールアドレス**
   - スコープ（データアクセス）：「スコープを追加」で **`https://www.googleapis.com/auth/drive`**（`.../auth/drive`）を追加
   - テストユーザー（対象）：**自分の Google アカウント** と **あきらの Google アカウント** を追加
   - 公開ステータスは「テスト」のままで構いません
4. 「API とサービス」→「認証情報」→「認証情報を作成」→「**OAuth クライアント ID**」
   - アプリケーションの種類：**ウェブ アプリケーション**
   - 名前：任意（例：ふたりアルバム Web）
   - 「**承認済みの JavaScript 生成元**」に次の 2 つを追加（**末尾にパスやスラッシュを付けない**）
     - `https://p418822san-dev.github.io`
     - `http://localhost:8000`
   - 「承認済みのリダイレクト URI」は空のままで構いません
   - 「作成」
5. 表示された **クライアント ID**（`xxxxxxxx.apps.googleusercontent.com` の形）を控える
   - クライアント **シークレット** は使いません。どこにも貼らないでください

### 3. クライアント ID を設定して push

1. `js/config.js` を開き、`gdrive.clientId` の `""` の中にクライアント ID を貼る
   ```js
   clientId: "1234567890-xxxxxxxx.apps.googleusercontent.com",
   ```
2. 同じファイルの `storage.backend` が `"gdrive"` になっていることを確認する
3. 変更を commit して push する
   ```sh
   git add js/config.js
   git commit -m "Drive 連携のクライアント ID を設定"
   git push
   ```
   （GitHub Pages への反映には数分かかります）
